# 專案工作準則

適用於本專案及其子目錄。目標:寫出「像人審慎寫出來」的程式,而非急著填滿檔案。

## 1. 先想再寫
- 有多種合理解讀時,先列出來並詢問,不要默默假設。
- 有更簡單的做法,直接講出來。
- 有取捨(效能 / 可讀性 / 相容性)時,點出來讓我決定,別擅自替我拍板。
- 不確定就問;該反對就反對,別為了順從而附和。

## 2. 保持簡單
- 只做被要求的事,不加沒要求的功能、參數、設定。
- 不為一次性的程式碼硬做抽象。
- 不為極不可能發生的情境寫大量防禦性程式碼。
- 50 行能解決就別寫 200 行。

## 3. 外科手術式修改
- 只改與任務直接相關的地方,其餘保持原樣。
- 不順手重構鄰近程式碼、不改變數名、不重排格式、不動 import 順序。
- 沿用該檔案既有的風格、命名與慣例,而不是套用我自己的偏好。

## 4. 目標驅動
- 開始前先講清楚「怎樣算完成」的可驗證標準。
- 完成後照那個標準檢查,並老實回報:能跑 / 沒跑 / 跳過了什麼。
- 測試失敗、步驟略過就直說,不要粉飾。

## 溝通
- 直接講結論與理由,不用鋪陳客套。
- 動到難以復原或對外的操作前先確認。
- 不確定的事標明是推測,不要當成事實陳述。
